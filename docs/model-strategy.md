# Bedrock Model Strategy

Health1004 is taxonomy-first. Bedrock is used to assist retrieval and generate source-grounded summaries, not to become the product itself.

## Current Default Profile

| Purpose | Model | Why |
| --- | --- | --- |
| Primary answer generation | `anthropic.claude-haiku-4-5-20251001-v1:0` | Better Korean answer quality, cautious wording, and citation-friendly synthesis |
| Fallback answer generation | `amazon.nova-2-lite-v1:0` | AWS-native fallback if the primary answer model is unavailable |
| Passage and query embeddings | `amazon.titan-embed-text-v2:0` | AWS-owned text embedding model, simple synchronous API, no Cohere dependency |
| Reranking | disabled, `ENABLE_RERANK=false` | Avoids an extra model dependency and cost until evaluation proves it is needed |

Equivalent environment configuration:

```bash
BEDROCK_CHAT_MODEL_ID=anthropic.claude-haiku-4-5-20251001-v1:0
BEDROCK_FALLBACK_CHAT_MODEL_ID=amazon.nova-2-lite-v1:0
BEDROCK_EMBED_MODEL_ID=amazon.titan-embed-text-v2:0
VECTOR_DIMENSION=1024
ENABLE_RERANK=false
```

The backend also accepts these alias names for operator convenience:

```bash
ANSWER_MODEL_ID=anthropic.claude-haiku-4-5-20251001-v1:0
FALLBACK_ANSWER_MODEL_ID=amazon.nova-2-lite-v1:0
EMBEDDING_MODEL_ID=amazon.titan-embed-text-v2:0
```

## Why This Is The Default

The user-visible quality mostly comes from the answer model. Claude Haiku 4.5 is the preferred answer writer because the archive needs careful Korean/English phrasing, source-grounded summaries, and medical-safety restraint.

The retrieval layer should be boring and stable. Titan Text Embeddings V2 keeps the default retrieval stack on AWS-owned infrastructure and removes the previous Cohere embedding dependency. Taxonomy, aliases, metadata filters, keyword scoring, and citations still do most of the product work.

Reranking is off by default. A reranker can help later, but it adds another model lifecycle, another permission, and another charge per query. Enable it only after evaluation shows clear benefit.

## Fallback Behavior

Answer generation tries `BEDROCK_CHAT_MODEL_ID` first. If that Bedrock Converse call fails, the backend tries `BEDROCK_FALLBACK_CHAT_MODEL_ID`.

Fallback applies only to answer generation. It does not change embeddings or rebuild vectors.

Terraform grants runtime IAM access to the primary answer model, fallback answer model, embedding model, and Bedrock inference profiles.

## Embedding Compatibility

Embeddings are not interchangeable. A vector bundle built with Cohere must not be searched with Titan query vectors, and a Titan bundle must not be searched with another embedding model unless it has been rebuilt.

The vector bundle records:

- `embedding_model_id`
- `embedding_dimension`
- `created_at`
- `record_count`

At query time, the backend reads the active vector bundle metadata and embeds the user query with the same recorded model and dimension. This prevents silently mixing embedding spaces during migration.

At ingestion time, existing vector records are reused only when the current configured embedding model and vector dimension match the existing vector bundle metadata.

## Changing The Answer Model

Changing the answer model is low risk:

1. Update `BEDROCK_CHAT_MODEL_ID`.
2. Update `BEDROCK_FALLBACK_CHAT_MODEL_ID` if needed.
3. Ensure IAM allows both model ARNs.
4. Redeploy or restart the backend.
5. Run a few `/query` checks and `scripts/evaluate_taxonomy_retrieval.py`.

No re-ingestion is required for answer-only changes.

## Changing The Embedding Model

Changing `BEDROCK_EMBED_MODEL_ID` requires a full vector rebuild:

```bash
python scripts/ingest.py --pdf-dir ./pdfs --s3-prefix raw-pdfs/ --force --report-path outputs/ingestion_reembed.json
python scripts/tag_passages.py --source existing --force --report outputs/taxonomy_report.json
python scripts/reindex_with_taxonomy.py --rebuild
python scripts/evaluate_taxonomy_retrieval.py
```

If the corpus lives outside `./pdfs`, pass the real PDF directory. For the one-time 3tan upload workflow, run the project-specific upload script after confirming `.env` contains the new embedding model.

## What Not To Do

- Do not point queries at a vector bundle generated by a different embedding model.
- Do not switch back to Cohere Command R for answer generation; it is not part of the default model profile.
- Do not enable reranking as a default cost unless evaluation shows it improves Korean retrieval enough to justify the dependency.
- Do not commit `.env`, Bedrock API keys, AWS credentials, Terraform state, or generated corpus artifacts.
